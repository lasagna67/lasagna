# company

Связка клиента с компанией. Компания — заёмщик: ЮЛ (ИНН 10 цифр, ЕГРЮЛ) или ИП (ИНН 12 цифр, ЕГРИП). Пользователь становится её представителем двумя способами:

- руководитель подтверждает полномочия КЭП: ЮЛ — генеральный директор из ЕГРЮЛ (`ceo`), ИП — сам предприниматель (`owner`). Получает право подписи;
- руководитель приглашает сотрудника по email (`cfo`, `accountant`, `finance_officer`, `authorized_employee`). Без права подписи.

ИНН не секрет — реестры публичные, поэтому одного ИНН для связки недостаточно. Ключ — КЭП руководителя. Внешние системы: registry-mock (`REGISTRY_URL`) и esign-mock (`ESIGN_URL`).

## Подключение компании (фронт)

Все ручки под `/api/v0/companies`, только для роли `client`, с токеном.

1. `GET /companies/lookup?inn=...` — карточка из реестра для подтверждения «это ваша компания?». Ничего не сохраняет.
2. `POST /companies/challenges {"inn"}` — заявление о подключении: `challenge_id` и текст `data`. Живёт 5 минут, одноразовое.
3. В браузере, напрямую в esign-mock (`http://localhost:8084`): `GET /v1/certificates` — список сертификатов, пользователь выбирает свой; `POST /v1/sign {"certificate_serial", "pin", "data"}` — подпись. PIN не проходит через бекенд.
4. `POST /companies {"challenge_id", "signature"}` — бекенд проверяет подпись в esign-mock, заново запрашивает реестр и сверяет: для ЮЛ сертификат выдан на эту организацию и владелец — руководитель из ЕГРЮЛ; для ИП ИНН владельца равен ИНН ИП.

Заявление тратится при любом исходе шага 4: после ошибки начинайте с шага 2.

| Код | Когда |
| --- | --- |
| 403 | Сертификат не руководителя: сотрудник, бывший директор, чужая компания |
| 410 | Заявление истекло, уже использовано или создано другим пользователем |
| 422 | Подпись не прошла проверку: изменён текст, сертификат отозван или просрочен |
| 503 | Реестр или УЦ недоступны |

Повторное подключение той же компании обновляет данные реестра и роль: например, приглашённый бухгалтер стал директором.

## Представители

- `GET /companies` — мои компании с моей ролью (`membership.position`, `membership.can_sign`).
- `GET /companies/{id}`, `GET /companies/{id}/members` — любому участнику; не участнику — 404, как будто компании нет.
- `POST /companies/{id}/members {"email", "position"}` — только руководитель; клиент должен быть уже зарегистрирован.
- `DELETE /companies/{id}/members/{user_id}` — руководитель удаляет сотрудника, сотрудник может выйти сам. Руководителя удалить нельзя (409).

## Проверка доступа в других модулях

`CompanyService.Membership(ctx, companyID, userID)` возвращает компанию и роль пользователя в ней или `companyerrors.ErrCompanyNotFound`, если пользователь не участник. Для действий с обязательствами (подписание договора) проверяйте `membership.Member.CanSign`.

```go
membership, err := companies.Membership(ctx, companyID, claims.UserID)
if errors.Is(err, companyerrors.ErrCompanyNotFound) {
	return ErrApplicationNotFound
}
if !membership.Member.CanSign {
	return ErrNotSigner
}
```

Статус из реестра (`business_status`: `active`, `reorganizing`, `terminated`) модуль только хранит. Стоп-факторы — дело кредитного процесса.
