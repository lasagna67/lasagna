# Registry Mock

Отдельный HTTP-сервис на Go 1.22+ и стандартной библиотеке, имитирующий ЕГРЮЛ/ЕГРИП. Загружает массив компаний из JSON один раз при запуске и ищет записи по ИНН в памяти.

## Запуск

Команды выполняются из `lasagna/backend/registry-mock`:

```powershell
go run .
```

По умолчанию файл данных: `testdata/companies.json`, порт: `8081`. Поместите собственный готовый массив компаний в этот файл; сервис его не создаёт и не изменяет. Относительный путь разрешается от текущего рабочего каталога.

Существующий файл в корне `registry-mock` можно использовать без перемещения:

```powershell
$env:REGISTRY_DATA_PATH = './companies.json'
go run .
```

Настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `REGISTRY_DATA_PATH` | `testdata/companies.json` | Путь к JSON-массиву компаний |
| `PORT` | `8081` | Порт HTTP-сервера |

Если файл недоступен, JSON повреждён, вход не является массивом или ИНН повторяется, приложение завершается с ошибкой загрузки до запуска HTTP-сервера. После изменения данных сервис нужно перезапустить.

## API

```powershell
curl.exe http://localhost:8081/health
curl.exe http://localhost:8081/v1/companies/7705005410
```

`GET /health` возвращает `200` и `{"status":"ok"}`.

`GET /v1/companies/{inn}` возвращает публичные регистрационные сведения. Метаданные `metadata` загружаются во внутреннюю модель, но отсутствуют в HTTP-ответе. У ИП отсутствующие `kpp`, `capital`, `reorganization` опускаются; неизвестный адрес возвращается как `"address":null`. Идентификаторы передаются строками, сумма капитала — целым числом копеек.

В синтетических данных `entity_type` принимает значения `ЮЛ` (юридическое лицо) и `ИП` (индивидуальный предприниматель). Репозиторий загружает их как строки, Service передаёт в Handler, а API возвращает без преобразования. Значения `source`: `ЕГРЮЛ` для юридических лиц и `ЕГРИП` для индивидуальных предпринимателей.

| Статус | Код ошибки | Условие |
| --- | --- | --- |
| `200` | — | Компания найдена |
| `400` | `INVALID_INN` | ИНН не состоит из 10 или 12 ASCII-цифр |
| `404` | `COMPANY_NOT_FOUND` | ИНН отсутствует в реестре |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка; детали остаются в серверном журнале |
| `405` | `METHOD_NOT_ALLOWED` | Для эндпоинта использован метод, отличный от GET |
| `404` | `NOT_FOUND` | Неизвестный маршрут |

Формат ошибки:

```json
{"error":{"code":"COMPANY_NOT_FOUND","message":"Company not found"}}
```

Контрольные цифры ИНН на первом этапе не проверяются.

## Устройство

- `main.go`: конфигурация, сборка зависимостей и HTTP-сервер с таймаутами.
- `internal/handler`: маршруты, HTTP-статусы, JSON-ответы и явный публичный DTO без метаданных.
- `internal/service`: проверка ИНН и вызов интерфейса `Repository`, объявленного в этом пакете.
- `internal/repository`: чтение JSON при запуске и индекс `map[string]model.Company`, реализация `JSONRepository`.
- `internal/model`: вложенные доменные структуры и `ErrCompanyNotFound`.

Зависимости передаются через конструкторы. Handler вызывает Service; Service вызывает Repository. Handler не читает файл, Service не знает о JSON и HTTP. Ожидаемые ошибки оборачиваются с `%w` и различаются через `errors.Is`. Контекст HTTP-запроса передаётся до репозитория.

## Проверки

```powershell
go fmt ./...
go vet ./...
go test ./...
go build ./...
```

Тесты создают JSON только во временных каталогах `t.TempDir()` либо используют тестовые реализации интерфейсов. Наличие пользовательского `companies.json` для тестов не требуется.

Юнит-тесты находятся в файлах `*_test.go` без суффикса `_integration`: они проверяют конфигурацию, Service с подставным Repository и Handler с подставным Service.

Интеграционные тесты вынесены в отдельные файлы:

- `internal/handler/registry_integration_test.go`: цепочка Handler → Service → Repository с временным JSON.
- `internal/repository/json_repository_integration_test.go`: загрузка и поиск с использованием реальной файловой системы.
- `main_integration_test.go`: ошибка запуска при недоступном файле данных.

Все интеграционные тесты имеют префикс `TestIntegration`. Обычный `go test ./...` запускает оба набора. Для раздельного запуска:

```powershell
go test ./... -skip Integration
go test ./... -run Integration
```
