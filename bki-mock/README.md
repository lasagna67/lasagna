# BKI Mock

Отдельный HTTP-сервис на Go 1.22+ и стандартной библиотеке для получения синтетических кредитных историй. Архитектура и стиль соответствуют Registry Mock: Handler → Service → Repository, интерфейсы у потребителей, зависимости через конструкторы, стандартный `net/http` и `log/slog`.

## Запуск

Из каталога `lasagna/bki-mock`:

```powershell
go run .
```

Сервис запускается отдельно от Registry Mock, без обращений к нему, базе данных или внешним БКИ.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `8082` | HTTP-порт |
| `BKI_DATA_PATH` | `testdata/bki.json` | Путь к JSON-массиву кредитных отчётов |

Относительный путь считается от текущего рабочего каталога. Для другого файла:

```powershell
$env:BKI_DATA_PATH = 'D:/data/bki.json'
$env:PORT = '9092'
go run .
```

При отсутствии файла, повреждённом JSON, неверной структуре кредитной записи или дублировании кредитного ИНН/business_id приложение завершается с понятной ошибкой до запуска HTTP-сервера. Данные загружаются один раз; после изменения файла сервис нужно перезапустить. Приложение только читает существующие данные.

## API

`GET /health` возвращает `200` и `{"status":"ok"}`.

Единственная бизнес-ручка — `GET /v1/credit-reports/{inn}`. Она получает кредитную историю по ИНН в пути, как ручки Registry Mock:

```http
GET /v1/credit-reports/6671986865
```

`inn` — обязательный параметр пути из 10 или 12 ASCII-цифр. JSON-тело не требуется. Неверный формат ИНН возвращает `400 INVALID_INN`; проверка контрольных цифр не выполняется.

Пример запроса к существующему профилю без кредитной истории:

```powershell
Invoke-RestMethod -Method Get -Uri 'http://localhost:8082/v1/credit-reports/6671986865'
```

Ответ `200 OK`:

```json
{
  "business_id": "business_004",
  "inn": "6671986865",
  "status": "ok",
  "report_date": "2026-10-20",
  "report": {
    "has_credit_history": false,
    "history_months": 0,
    "loans": []
  }
}
```

Отсутствие кредитной истории у найденного заёмщика возвращается как успешный отчёт с `has_credit_history: false`. `404` означает, что кредитной записи по ИНН нет в файле.

Пример ИП с кредитами:

```powershell
Invoke-RestMethod -Method Get -Uri 'http://localhost:8082/v1/credit-reports/770761836401'
```

Ответ содержит исходные `business_id`, `inn`, `status`, `report_date` и `report` с массивом `loans`. Набор полей соответствует существующему JSON. Все денежные значения — целые рубли, в Go они хранятся в `int64` без промежуточного `float64`. Отдельный DTO не требуется.

## Данные

В `testdata/bki.json` находятся только 20 кредитных отчётов: 10 ИП и 10 ООО. Repository загружает этот массив и строит индекс по ИНН. Повторы ИНН или `business_id` считаются ошибкой. Поле `business_id` сохраняется в ответе как часть исходного отчёта.


## Ошибки и логирование

Формат ошибок совпадает с Registry Mock:

```json
{"error":{"code":"CREDIT_HISTORY_NOT_FOUND","message":"Credit history not found"}}
```

| Статус | Код | Условие |
| --- | --- | --- |
| `400` | `INVALID_INN` | Некорректный формат ИНН |
| `404` | `CREDIT_HISTORY_NOT_FOUND` | Кредитная запись по ИНН не найдена |
| `404` | `NOT_FOUND` | Неизвестный маршрут |
| `405` | `METHOD_NOT_ALLOWED` | Неверный HTTP-метод; ответ содержит `Allow` |
| `500` | `INTERNAL_ERROR` | Непредвиденная ошибка; её детали не раскрываются в ответе |

Ожидаемые ошибки различаются через `errors.Is`. Контекст запроса передаётся до Repository. В `main` создаётся общий JSON-логгер `slog` с полем `service=bki-mock`; внутренние ошибки HTTP-сервера направлены в тот же логгер. Ошибки логируются на границе приложения без дублирования в каждом слое.

Таймауты совпадают с Registry Mock: заголовки — 5 секунд, чтение и запись — по 10 секунд, простой соединения — 60 секунд.
