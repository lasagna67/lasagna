# ESign Mock

Отдельный HTTP-сервис на Go 1.22+ и стандартной библиотеке, имитирующий квалифицированную электронную подпись (КЭП): удостоверяющий центр и криптопровайдер с токеном. Архитектура и стиль как у Registry Mock: Handler → Service → Repository, зависимости через конструкторы, `net/http` и `log/slog`.

В реальности руководитель ООО или ИП получает КЭП в УЦ ФНС, закрытый ключ хранится на токене под PIN-кодом, а подписывает браузерный плагин криптопровайдера. Мок воспроизводит этот смысл: сертификаты «установлены на компьютере», подписать можно только с PIN-кодом, а проверить подпись может кто угодно.

## Зачем он нужен

Бекенд подтверждает полномочия при подключении компании:

1. Бекенд выдаёт строку для подписи (`POST /api/v0/companies/challenges`).
2. Фронт получает список сертификатов (`GET /v1/certificates`), пользователь выбирает свой и вводит PIN, фронт подписывает строку (`POST /v1/sign`). Запрос идёт из браузера напрямую в мок, PIN не проходит через бекенд банка.
3. Бекенд проверяет подпись (`POST /v1/verify`) и сверяет владельца сертификата с руководителем из ЕГРЮЛ или с ИНН ИП из ЕГРИП (registry-mock).

## Запуск

Из каталога `lasagna/esign-mock`:

```powershell
go run .
```

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `8084` | HTTP-порт |
| `ESIGN_DATA_PATH` | `testdata/certificates.json` | Путь к JSON-массиву сертификатов |
| `ESIGN_KEY_SECRET` | `esign-mock-demo-secret` | Секрет, из которого выводятся ключи сертификатов |
| `ALLOWED_ORIGINS` | `*` | Источники браузерных запросов через запятую (CORS) |

Ключи Ed25519 выводятся детерминированно из `ESIGN_KEY_SECRET` и серийного номера, поэтому подписи остаются проверяемыми после перезапуска. Зная секрет, подпись можно вычислить без PIN: на публичном стенде задайте свой `ESIGN_KEY_SECRET`.

При отсутствии файла, повреждённом JSON, неверных полях сертификата или повторе серийного номера приложение завершается с ошибкой до запуска HTTP-сервера.

## API

`GET /health` возвращает `200` и `{"status":"ok"}`.

### `GET /v1/certificates`

Сертификаты «на компьютере пользователя», без PIN-кодов:

```json
{"certificates":[{
  "serial": "0BFD0184037F4867",
  "type": "legal_entity_head",
  "subject": {"full_name": "Кедрова Анна Викторовна", "inn": "770586906621", "position": "Генеральный директор"},
  "organization": {"name": "ООО «Кедровый контур Демо»", "inn": "7705005410"},
  "issuer": "УЦ ФНС России (демо)",
  "valid_from": "2026-01-15",
  "valid_to": "2027-01-15",
  "status": "valid"
}]}
```

`type`: `legal_entity_head` — руководитель ЮЛ, в сертификате есть организация; `individual_entrepreneur` — ИП, ИНН владельца совпадает с ИНН бизнеса; `individual` — физлицо без организации, например сотрудник. `status`: `valid` или `revoked`. Даты действия включительно, по UTC.

### `POST /v1/sign`

```json
{"certificate_serial": "0BFD0184037F4867", "pin": "12345678", "data": "строка от бекенда"}
```

Ответ `200`:

```json
{"signature": "eyJzZXJpYWwiOi...", "signed_at": "2026-10-21T09:15:00Z", "certificate": {"serial": "0BFD0184037F4867", "...": "..."}}
```

`signature` — непрозрачная строка base64url. Внутри серийный номер сертификата, время подписания и подпись Ed25519 над `signed_at + "\n" + data`. Данные — до 64 КБ.

### `POST /v1/verify`

```json
{"data": "строка от бекенда", "signature": "eyJzZXJpYWwiOi..."}
```

Ответ всегда `200`, если подпись удалось разобрать. Результат проверки в поле `valid`:

```json
{"valid": true, "signed_at": "2026-10-21T09:15:00Z", "certificate": {"...": "..."}}
{"valid": false, "reason": "signature_mismatch", "signed_at": "...", "certificate": {"...": "..."}}
```

| `reason` | Когда |
| --- | --- |
| `signature_mismatch` | Данные или подпись изменены |
| `unknown_certificate` | Сертификата с таким серийным номером нет |
| `certificate_revoked` | Сертификат отозван |
| `certificate_expired` | На момент подписания сертификат не действовал |

### Ошибки

Формат как у остальных моков: `{"error":{"code":"INVALID_PIN","message":"Invalid PIN"}}`.

| Статус | Код | Условие |
| --- | --- | --- |
| `400` | `INVALID_REQUEST` | Не JSON, нет обязательных полей, данные больше 64 КБ |
| `400` | `MALFORMED_SIGNATURE` | Строку подписи не удалось разобрать |
| `403` | `INVALID_PIN` | Неверный PIN |
| `404` | `CERTIFICATE_NOT_FOUND` | Нет сертификата с таким серийным номером |
| `422` | `CERTIFICATE_REVOKED` | Сертификат отозван |
| `422` | `CERTIFICATE_EXPIRED` | Сертификат сейчас не действует |
| `404` | `NOT_FOUND` | Неизвестный маршрут |
| `405` | `METHOD_NOT_ALLOWED` | Неверный HTTP-метод, ответ содержит `Allow` |
| `500` | `INTERNAL_ERROR` | Непредвиденная ошибка |
